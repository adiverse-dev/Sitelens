# SiteLens

> Open-source technical SEO and website auditing API built with Node.js, Express, Playwright, and Lighthouse.

SiteLens audits a live website in a real Chromium browser, captures technical SEO signals, runs Lighthouse scoring, generates a screenshot, and returns a structured JSON report through a simple REST API.

Repository: [https://github.com/adiverse-dev/Sitelens](https://github.com/adiverse-dev/Sitelens)

---

## Overview

SiteLens is a backend-first technical SEO auditing platform. The current backend milestone completes **Phase 6 link auditing**, while dashboards, persistence, authentication, structured-data auditing, scoring, and report exports remain future work.

It is designed for:

- Developers who want a practical website audit API
- SEO freelancers who need structured technical audit data
- Recruiters reviewing backend, automation, and technical SEO skills
- Future SaaS-style dashboards for website quality monitoring

SiteLens combines browser automation, Lighthouse metrics, metadata extraction, multi-page crawling, structured link evidence, SSRF-safe link checks, site-wide link-health reporting, and deterministic rule-based recommendations.

---

## Problem Statement

Websites can appear visually correct while still having technical SEO, accessibility, performance, or reliability issues. Common problems include missing canonicals, incomplete social metadata, poor heading structure, missing image alt text, JavaScript console errors, failed network requests, and weak Lighthouse scores.

Manual inspection requires browser DevTools, SEO extensions, network monitoring, HTML review, screenshot capture, and performance tooling.

SiteLens automates that first audit layer and returns clean JSON that can later power dashboards, reports, scoring systems, and AI-assisted recommendations.

## How It Works

```text
User submits URL
        |
        v
Express receives POST /audit
        |
        v
URL is validated
        |
        v
Playwright launches Chromium
        |
        v
Page loads in a real browser
        |
        v
Technical SEO, metadata, headings, images, console, and network data are collected
        |
        v
Lighthouse scores are generated
        |
        v
Recommendations are created
        |
        v
Structured JSON audit result is returned
```

`POST /crawl` reuses the page-audit pipeline across a bounded queue, applies link checks after page collection, and then builds the additive site-wide report:

```text
Validated seed URL
        |
        v
Bounded page queue and browser audits
        |
        v
Structured page-level link evidence
        |
        v
Deduplicated SSRF-safe target checks and redirect resolution
        |
        v
Site-wide linkHealth aggregation and deterministic actions
```

### `POST /crawl`

Runs a bounded multi-page crawl. Existing `siteWide`, crawl metadata, and page results are preserved; `linkChecks` describes execution and `linkHealth` describes findings and deterministic actions.

#### Request Body

```json
{
  "url": "https://example.com",
  "options": {
    "maxPages": 25,
    "maxDepth": 2,
    "concurrency": 2,
    "runLighthouse": false
  }
}
```

Request limits are `maxPages` 1–200, `maxDepth` 0–10, and `concurrency` 1–5. Lighthouse is disabled by default in crawl mode.

#### Link Contract

- Page `links.internal` and `links.external` retain every anchor occurrence. `links.discarded` contains unusable links and is never classified as broken.
- `linkChecks.uniqueTargets` counts normalized starting targets; `linkHealth.summary.totalOccurrences` counts retained anchor occurrences.
- Check `state`, `statusCode`, and `location` describe the first response. `finalState`, `finalStatusCode`, and `finalUrl` describe the resolved outcome.
- Health values are `healthy`, `redirected`, `restricted`, `broken`, `unreachable`, `blocked`, and `unchecked`. The site report adds `unknown` for a missing or invalid check contract.
- `isBroken` is `true` only for deterministic broken outcomes, `false` for healthy/redirected/restricted outcomes, and `null` for blocked, unchecked, timeout, DNS, or uncertain network outcomes.
- Redirect chains are stored once per site-wide target and remain available on page-level checks. Action groups contain URL references rather than duplicate target records.
- The site report orders targets by priority, affected-page count, and URL. All issue and action references resolve to a unique target record.

#### Remediation Codes

| Code | Trigger | Owner |
| --- | --- | --- |
| `resolve_link_classification_conflict` | Target appears as both internal and external | `review` |
| `repair_link_check_contract` | Missing or invalid normalized check contract | `developer` |
| `fix_redirect_loop` | `redirect_loop` | `developer` |
| `shorten_redirect_chain` | `too_many_redirects` | `developer` |
| `add_missing_redirect_location` | `missing_location` | `developer` |
| `fix_invalid_redirect_location` | `invalid_location` | `developer` |
| `replace_unsupported_redirect_status` | `unsupported_redirect_status` | `developer` |
| `review_blocked_redirect_destination` | `blocked_destination` | `review` |
| `replace_unsupported_redirect_scheme` | `unsupported_scheme` | `developer` |
| `remove_redirect_credentials` | `credentials_not_allowed` | `developer` |
| `replace_or_remove_broken_internal_link` | Broken internal target | `developer` |
| `review_or_replace_broken_external_link` | Broken external target | `content` |
| `update_internal_redirect` | Internal redirect ending successfully | `developer` |
| `review_external_redirect` | External redirect ending successfully | `content` |
| `retry_unreachable_internal_target` | Unreachable internal target | `developer` |
| `retry_unreachable_external_target` | Unreachable external target | `review` |
| `verify_restricted_internal_target` | Restricted internal target | `site_owner` |
| `verify_restricted_external_target` | Restricted external target | `review` |
| `review_target_limit_configuration` | Unchecked because target limit was reached | `site_owner` |
| `review_unchecked_target` | Other unchecked result | `review` |
| `review_blocked_internal_target` | Other blocked internal target | `review` |
| `review_blocked_external_target` | Other blocked external target | `review` |

Remediation is deterministic and rule-based. It does not call an AI service, invent replacement URLs, or promise ranking improvements. Classification conflict takes precedence over check-contract problems; check-contract problems take precedence over redirect-specific rules; redirect-specific rules take precedence over generic health guidance.

#### Link-Check Limits and Security

Link-check settings are server-side environment configuration and are not accepted as `POST /crawl` options:

| Setting | Default | Hard ceiling |
| --- | ---: | ---: |
| `LINK_CHECK_MAX_TARGETS` | 200 unique targets | 1000 |
| `LINK_CHECK_CONCURRENCY` | 4 simultaneous checks | 10 |
| `LINK_CHECK_MAX_REDIRECTS` | 5 followed transitions | 10 |
| `CRAWLER_REQUEST_TIMEOUT_MS` | 5000 ms overall per target | 15000 ms |

Each initial target and redirect hop is independently validated against private, loopback, link-local, metadata, reserved, and disallowed destinations. The HTTP connection is pinned to a validated IP, automatic redirects are disabled, and only 301, 302, 303, 307, and 308 are followed. Checks send `HEAD` first and use a bounded `GET` fallback only for 405 or 501.

Known limitations: only the first validated IP is attempted per hop; DNS lookup itself cannot be cancelled after the overall deadline; uncertain external failures remain `unreachable`, not confirmed broken; normalized starting targets preserve query strings because queries participate in target identity and should therefore be treated as potentially sensitive evidence; no overall Site Health score is produced.

## Getting Started

### 1. Clone the Repository

```bash
git clone https://github.com/adiverse-dev/Sitelens.git
cd Sitelens
```

### 2. Install Dependencies

```bash
npm install
```

### 3. Install Playwright Browsers

```bash
npx playwright install
```

### 4. Run the Server

```bash
npm start
```

The API server runs at:

```text
http://localhost:5000
```

The long-term goal of SiteLens is to become a complete open-source technical SEO auditing platform.

A user should be able to enter any website URL and receive a clear report covering technical SEO, social metadata, accessibility, performance, reliability, screenshots, prioritized recommendations, and exportable reports.

Future versions can add a React dashboard, saved audit history, team workflows, PDF reports, and AI-generated explanations for developers, founders, freelancers, agencies, and non-technical website owners.

---

## Status

**Phase 6 - Complete**

The backend audit engine now includes bounded multi-page crawling, structured link evidence, SSRF-safe unique-target checks, redirect-chain validation, final link-health classification, site-wide aggregation, and deterministic remediation actions in addition to the existing page-audit pipeline.

The next milestone is **Phase 7A**, focused on deterministic structured-data auditing without changing the completed Phase 6 contracts.
